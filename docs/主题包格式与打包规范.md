# ThemePackager 主题包格式与打包规范

> 适用对象：使用本工具的视觉设计师与主题资源制作者
> 适用范围：传音系（HiOS / XOS / itel）系统预制主题（prebuilt）的资源组织、校验与打包

---

## 一、工具是做什么的

设计师提供视觉资源（图标、壁纸、预览图、动态图标绘制资源、字体等），工具负责三件事：

```
设计资源  ──►  校验（validator）  ──►  打包（packager）  ──►  主题包文件
                结构 / 命名 /           目录 → zip →            *.xth
                格式 / 尺寸             图片统一转 webp
```

- **校验不通过（存在错误）时无法打包**，警告不阻断但建议修正
- 最终产物是一个 `.xth` 文件，本质是一个 zip，**zip 根目录直接放置 manifest.json**（不带外层文件夹）

---

## 二、主题的两个维度

一个主题包由两个正交维度决定它的规则：

### 2.1 包类型（manifest.json 中的 `type`）

| type | 含义 | 包含内容 |
|:---:|---|---|
| `0` | **完整主题** | 图标 + 壁纸 + 预览图 + 多应用资源覆盖（app/） |
| `1` | **图标主题** | 仅图标 + 桌面（launcher）资源，不含壁纸与预览图 |

### 2.2 图标风格与 color_mode 样式

图标资源格式（每个应用图标的构成）：

| 资源格式 | 判定条件 | 每个应用图标的构成 |
|---|---|---|
| **normal（非自适应）** | 无 `_bg` / `_top` 分层文件 | 一张绘制好的单图：`<包名>.webp` |
| **adaptive（自适应）** | 存在 `_bg` / `_top` 分层文件 | 至少两张：`<包名>_bg.webp`（背景层）+ `<包名>_top.webp`（前景层） |
| **mono（可着色）** | `color_mode = "mono"`，必属 adaptive | 三张：`_bg.webp` + `_top.webp` + `<包名>_monochrome.xml`（上色资源） |

`color_mode` 四种样式（不配置按 `default` 处理）：

| color_mode | 含义 | 图标资源要求 |
|:---:|---|---|
| `default` | 默认样式，无特殊效果，配什么显示什么 | normal 或 adaptive 均可 |
| `glass` | 玻璃样式 | **必须 adaptive** |
| `foreground_color` | 暗黑样式（系统中以此标识暗色模式） | **必须 adaptive** |
| `mono` | 可着色样式，图标可上色成任意颜色 | **必须 adaptive + `_monochrome.xml`** |

### 2.3 description.xml 的强制约定

`icons/description.xml` 中的 `support_adaptive_icon_feature` 必须与图标风格一致：

| 图标风格 | 要求 |
|---|---|
| normal（仅 default 样式可选） | 配置为 `value="0"` 或 **不配置该节点** |
| adaptive（含 glass / foreground_color / mono） | **必须**配置 `<support_adaptive_icon_feature value="1"/>` |

配置错误属于**错误（阻断打包）**，因为它决定手机端如何解析图标资源。

## 三、manifest.json 规范

```json
{
  "id": "98a89a79-a948-4531-8a4e-b261dXOS_default_theme",
  "type": 0,
  "version": 11,
  "app_resource_dir": "app",
  "author": "transsion",
  "name": "XOS",
  "description": "XOS",
  "color_mode": "default",
  "prebuilt": "1"
}
```

| 字段 | 必填 | 规则 |
|---|:---:|---|
| `id` | 是 | 主题唯一标识 |
| `type` | 是 | 只能为 `0`（完整主题）或 `1`（图标主题） |
| `version` | 是 | 主题包版本号，**大于 0 的整数**；资源每次更新至少 +1 |
| `app_resource_dir` | 是 | 应用资源覆盖目录名，固定为 `"app"` |
| `author` | 是 | 作者 / 团队 |
| `name` | 是 | 主题名称 |
| `description` | 是 | 主题描述 |
| `prebuilt` | 是 | 系统预制主题固定为**字符串** `"1"`（注意不是数字） |
| `color_mode` | 否 | 取值 `default` / `glass` / `foreground_color` / `mono`，不配置按 `default` 处理；非 default 必须搭配自适应图标资源 |
| `os_version` | 否 | 平台版本标识，按需配置 |

## 四、目录结构规范

### 4.1 完整主题（type = 0）

```
<主题名>/
├── manifest.json
├── icons/                    # 应用图标（见第五节）
├── preview/                  # 预览图（见第六节）
├── wallpapers/
│   └── drawable/
│       ├── wallpaper_home.webp   # 桌面壁纸
│       └── wallpaper_lock.webp   # 锁屏壁纸
└── app/                      # 应用资源覆盖（见第七节）
    └── <应用包名>/
        ├── drawable[-night][-xhdpi|-xxhdpi]/
        ├── values/
        ├── font/
        └── preview/
```

### 4.2 图标主题（type = 1）

```
<主题名>/
├── manifest.json
├── icons/                    # 应用图标
└── app/
    └── com.transsion.launcher3/   # 仅桌面资源
        ├── font/                  # 字体（.ttf / .otf）
        └── values/                # colors / strings / dimens / bools / arrays
```

> 图标主题中如果出现 preview/ 或 wallpapers/，校验会给出警告（这些属于完整主题资源）。

## 五、icons/ 图标规范

### 5.1 应用图标命名与配对

| 风格 | 文件 | 推荐尺寸 | 校验规则 |
|---|---|:---:|---|
| normal | `<包名>.webp` | 162 × 162 | 单图，无需配对 |
| adaptive | `<包名>_bg.webp` + `<包名>_top.webp` | 324 × 324 | **缺任一层即错误** |
| mono | 上两项 + `<包名>_monochrome.xml` | 324 × 324 | **三件套缺一即错误** |

- 命名以**应用包名**为主体，也支持 Activity 级（如 `com.android.dialer.ContactMainActivity_bg.webp`）与 alias 命名
- 所有图片资源**统一输出 webp**；投入 png/jpg 时工具在打包阶段自动转换，并给出提示
- 扩展名与文件真实内容不符（例如 JPEG 内容命名为 .png）会被嗅探出来并告警

### 5.2 monochrome 上色资源（仅 mono 主题）

`<包名>_monochrome.xml` 必须是合法的 **VectorDrawable**（包含 `<vector>` 根节点与 `pathData`），供系统单色化着色使用。

> 注意：主题包不参与 apk 编译，xml 在运行时直接解析。因此**不允许包含需要 aapt 编译期能力的元素**（见第八节"合法性边界"）。

### 5.3 兜底模板（未适配应用的通用处理）

| 文件 | 作用 |
|---|---|
| `icon_theme_background.webp` | 未适配应用图标的背景 |
| `icon_theme_foreground.webp` | 未适配应用图标的前景 |
| `icon_theme_mask.webp` | 未适配应用图标的裁切蒙版 |
| `description.xml` | 变换配置（matrix / 背景前景蒙版路径 / 饱和度 / 自适应开关） |

> 三张模板图与包内所有图片一样，统一为 **webp**；description.xml 中的路径引用也必须是 `.webp`。
> 用工具新建项目时会自动预置这三张默认模板图（取自样本默认资源），设计师后续上传正式资源替换即可，不会遗漏。

手机端对**没有单独适配的应用**，会用 mask 裁切原图标后叠加背景/前景，使全套图标风格统一。

### 5.4 特殊资源（不参与包名配对校验）

- `icon_style_preview.webp` —— 图标风格预览图
- `hios_dynamic_icons_clock_bg/_h/_m/_point` —— 动态时钟图标（背景/时针/分针/中心点）
- `com_android_launcher3_portal_ring_inner_holo.png`、`transsion_calendarbg` 等平台约定资源
- 文件夹 / 小部件图标（如 `x_freezr_folder_icon`、`lockscreen_widget_icon`）

## 六、preview/ 与 wallpapers/ 规范（完整主题）

| 目录 | 文件 | 规则 |
|---|---|---|
| `preview/` | `preview_lock_<n>.webp` | 锁屏预览图，`<n>` 从 0 起 |
| | `preview_unlock_<n>.webp` | 桌面预览图，**张数不限**，按设计师提供为准 |
| | `thumbnail.webp` | **可选**，主题缩略图 |
| `wallpapers/drawable/` | `wallpaper_home.webp` | 桌面壁纸 |
| | `wallpaper_lock.webp` | 锁屏壁纸 |

命名不符合 `preview_lock_<n>` / `preview_unlock_<n>` 的文件会被警告并忽略。

---

## 七、app/ 应用资源覆盖规范

- 一级目录为**应用包名**（含平台约定的公共目录如 `common_control`）
- 二级目录为 Android 资源目录，允许带限定符：
  `drawable`、`drawable-night`、`drawable-xhdpi`、`drawable-night-xxhdpi`、`values`、`font`、`preview` 等
- 支持 `.9.png` 九宫格图、`_hios` / `_xos` 平台后缀变体
- 字体支持 `.ttf` / `.otf`

## 八、校验规则总览

### 8.1 错误（阻断打包）

| 规则 | 说明 |
|---|---|
| manifest.json 缺失或 JSON 非法 | — |
| manifest 必填字段缺失 | 见第三节 |
| `type` 非 0/1 | — |
| `version` 非正整数 | — |
| 缺少 icons/ 目录 | — |
| adaptive 主题 description.xml 未配置 `support_adaptive_icon_feature=1` | normal 主题配成 1 同样报错 |
| adaptive 图标缺 `_bg` 或 `_top` | 逐包名报告 |
| mono 主题缺 `_monochrome.xml` | 逐包名报告 |
| monochrome 文件不是合法 VectorDrawable | 必须含 `<vector>` 与 `pathData` |
| 图片内容无法识别 | 文件损坏或非图片 |

### 8.2 警告（不阻断，建议修正）

| 规则 | 说明 |
|---|---|
| `prebuilt` 不是字符串 `"1"` | 数字 1/0 会告警 |
| `color_mode` 未知取值 | — |
| 图标非 webp | 打包时自动转换 |
| 扩展名与真实内容不符 | 如 JPEG 伪装 .png |
| 图标尺寸非推荐值 | normal 162 / adaptive 324 |
| 缺少兜底模板文件 | background / foreground / mask / description.xml |
| 完整主题缺 preview/ 或 wallpapers/ | — |
| 图标主题包含 preview/ 或 wallpapers/ | — |
| preview 命名不规范 | — |
| 存在 `_monochrome.xml` 但 color_mode 非 mono | — |
| app/ 下出现非标准资源目录名 | — |

### 8.3 monochrome 的合法性边界（重要）

主题包中的 xml **不参与 apk 编译**，由系统在运行时直接读取解析为 `VectorDrawable` 对象。因此从 SVG 转换 monochrome 时，只允许 VectorDrawable 运行时支持的元素与属性：

- 允许：`<vector>`、`<path>`（`pathData`、`fillColor`、`strokeColor`、`fillAlpha`、`strokeAlpha`、`strokeWidth`、`fillType`、`trimPath*`）、`<group>`（`rotation`、`scaleX/Y`、`translateX/Y`、`pivotX/Y`）、`<clip-path>`
- 禁止：任何 `aapt:` 命名空间内容（如编译期渐变 `<aapt:attr><gradient>`）、资源引用（`@color/xxx`、`?attr/xxx`）、`<bitmap>`、动画节点等

含有禁止元素的 SVG 属于**不合法输入**，转换出的 xml 将无法被系统正确读取，必须在制作环节剔除。

## 九、打包逻辑

1. 先执行完整校验，**存在错误即终止**
2. 遍历主题目录（自动跳过 `.DS_Store`、`Thumbs.db` 等系统垃圾文件）
3. **强制将全部图片统一转换为 webp**（quality 95，扩展名同步改写）——这是硬规则，主题包内不允许出现非 webp 图片；仅调试用 `--keep-format` 可跳过
4. 同步改写 `icons/description.xml` 中的图片路径引用（`.png/.jpg` → `.webp`），保证转换后引用不断裂
5. 以 zip（deflate 最高压缩级别）输出，**zip 根目录即 manifest.json**
6. 产物文件名后缀为 `.xth`

### 命令行用法

```bash
# 校验
node core/cli.js validate <主题目录>

# 打包（图片强制转 webp）
node core/cli.js pack <主题目录> <输出路径.xth>

# 调试用：保留图片原始格式
node core/cli.js pack <主题目录> <输出路径.xth> --keep-format
```

校验报告包含：主题画像（type / 图标风格 / color_mode）、资源统计、逐条错误与警告。

## 十、附：代码结构

```
core/
├── profiles.js    # 规则常量：类型、命名、尺寸、特殊文件清单（规则唯一来源）
├── imageInfo.js   # 图片内容嗅探：识别 PNG / JPEG / WebP 真实格式与尺寸
├── validator.js   # 校验器：本文第八节全部规则的实现
├── packager.js    # 打包器：zip → .xth，可选 webp 转换
└── cli.js         # 命令行入口：validate / pack
```

规则如需调整，只改 `profiles.js` 与 `validator.js`，不影响界面与打包。
